# TreeACI message-cache budget regression

Work log for the SimpleTT ACI performance regression observed after the
`treeaci-crate` persistent message-cache rewrite.

## Symptom

The downstream SGW SimpleTT pipeline in `NBlock` layout completed the same
R=10 workload in about 96 seconds at the older `codex/treeaci` revision. With
the persistent-cache evaluator at `c4851304` and `6cd1352`, it stalled during
`pi_rtau(r,tau) via aci`; sampled processes reached roughly 25--30 GiB of
physical footprint while the machine was heavily swapping.

## Diagnosis

The branch comparison and paired runtime measurements identify the regression
as `c2bc06d2 -> c4851304`, where the evaluator gained a persistent directed
message cache. The later `c4851304 -> 6cd1352` merge did not change
`cached_evaluator.rs`, so reverting the merge is not the relevant fix.

The cache was constructed with `usize::MAX` as its byte budget. During the
many changing batches generated by SimpleTT's greedy ACI pivot search, it
retained materialized message columns until teardown. The teardown stack
(`AciProduct -> CachedTreeTNProduct -> TreeTNCachedEvaluator ->
PackedMessageCache -> EagerTensor/free`) and the memory measurements match
the observed swap storm.

## Fix

`CachedEvaluatorOptions` now exposes `message_cache_max_bytes`. A zero budget
disables retention while preserving evaluation results; the default remains
`usize::MAX` for native TreeACI compatibility in this patch. The evaluator
also handles uncached slots explicitly when assembling a batch, so a zero
budget does not violate the cache's slot invariant.

The downstream SimpleTT ACI path opts out with a zero budget. The TreeACI path
continues to use the normal constructor and cache behavior.

## Validation

- The new zero-budget evaluator test was written red first and then passed.
- The focused cached-evaluator suite passes: 29 tests, 0 failures.
- The downstream TreeACI/SimpleTT Pi, W, and Sigma comparison passes.
- The patched R=10 NBlock SimpleTT run completes: Pi 60.3 s, Sigma 58.7 s,
  total 138.06 s, with about 1.26 GiB RSS and no multi-tens-of-GiB teardown.

The patched run is slower than the old `codex/treeaci` baseline because it
deliberately gives up persistent message retention for SimpleTT ACI, but it
completes within bounded memory and preserves the numerical result.

## Follow-up

The default `usize::MAX` budget preserves existing TreeACI behavior but is not
a long-term bounded-cache policy. A later change should choose a finite
default and expose cache statistics/clear semantics, then remeasure native
TreeACI and SimpleTT pipelines separately.
